# GODEYE Threat Model

**Method:** STRIDE across six trust boundaries.
**Commit:** `21b6733` (recon), suite added in `a8cad9b`.
**Status:** describes the system **as it is today**, not as intended. Every claim is
either backed by a location in `docs/audit/RECON.md` or marked as unverified.

A threat is listed as **OPEN** when nothing in the system prevents it, **PARTIAL** when
something does but incompletely, and **MITIGATED** when a control exists and has been
located. Findings ids (C-1, S-1 …) match RECON.md; `EXPLOIT:` names the RED test that
will prove the fix.

---

## Assets, ranked

| # | Asset | Where it lives | Why it ranks here |
|---|---|---|---|
| 1 | Platform credentials (FB page tokens, IG, TikTok, X, LinkedIn, Reddit, Telegram/Discord bot tokens) | `SocialConnection.encryptedCredentials`, AES-256-GCM | Theft = the attacker publishes as the customer's brand, to the customer's audience. Unrecoverable reputational damage. |
| 2 | `TOKEN_ENCRYPTION_KEY` | env, both API and engine | Decrypts every row of asset #1 at once. |
| 3 | `JWT_ACCESS_SECRET` | env, API only | Mints sessions for any user/org. Currently **also** signs OAuth state (C-1). |
| 4 | Tenant data (content, products, business profile, analytics) | Postgres, all `orgId`-scoped | Cross-tenant read is a breach; the business profile drives every AI output. |
| 5 | User credentials | `User.passwordHash` (argon2id), `User.mfaSecret` (encrypted) | Standard. Handled well. |
| 6 | Money | Paystack, `Subscription`, `AuditLog` marker rows | Idempotency defects give revenue away rather than steal it. |
| 7 | Compute / AI budget | Celery workers, Anthropic/OpenAI keys | Unmetered generation paths turn any account into a cost amplifier. |

## Trust boundary 1 — browser → API

Public internet to `api.godeyeautomation.com`. Carries a Bearer access token
(in-memory, 15 min) and a `godeye_refresh` cookie (httpOnly, 30 d, `path=/auth`).

| STRIDE | Threat | Status | Evidence / control |
|---|---|---|---|
| **S** | **A leaked OAuth `state` parameter authenticates as its subject.** State is signed with `JWT_ACCESS_SECRET` and `JwtAuthGuard` checks only signature and expiry. `state` is *designed* to transit Meta/TikTok/LinkedIn/Reddit and lands in their logs, browser history and `Referer`. | **OPEN — C-1, CRITICAL** | `connections.service.ts:235,275,303,340,374` vs `auth.service.ts:499`; guard `jwt-auth.guard.ts:27-28`. Demonstrated: `GET /auth/me` → **200**, `POST /auth/switch-org` → **200** with a full session. `EXPLOIT: c1-oauth-state-is-a-session` |
| **S** | Password guessing | **PARTIAL** | argon2id + 10/60s throttle on `/auth/login` — but the bucket is global (S-4), so the throttle protects nobody and locks out everybody. |
| **S** | Session fixation / refresh theft | **PARTIAL** | Rotation on refresh (`auth.service.ts:158`), hashed at rest. No reuse detection: a replayed token is rejected but the family is not revoked, so theft is never noticed. |
| **T** | CSRF on state-changing routes | **MITIGATED** | Writes require a Bearer header, which a cross-site form cannot set. |
| **T** | CSRF-logout / forced refresh | **OPEN, LOW** | Cookie is `SameSite=None` when cross-site (`auth.controller.ts:58-63`); `POST /auth/refresh` and `/auth/logout` take no CSRF token. Attacker cannot read the response but can rotate or destroy the session. |
| **R** | Attributing an action to a user | **PARTIAL** | `AuditLog` is written on the paths that matter, but `req.ip` is the proxy's for every row (S-4), so "who" is recorded and "from where" is not. |
| **I** | Route map and DTO disclosure | **OPEN — S-9** | `main.ts:72` mounts Swagger unconditionally. Publishes every route, every DTO, and hints like *"Connect X with an access token pair generated by hand"*. Makes C-1 trivial to find. `EXPLOIT: s5-s6-s9-config` |
| **I** | Error-message disclosure | **PARTIAL** | Engine 4xx bodies are forwarded verbatim to the client (`engine.service.ts:197-204`). Intentional for usability; needs a redaction pass. |
| **D** | **Self-DoS via a shared rate-limit bucket.** `trust proxy` is never set, so all 26 `@Throttle` overrides plus the global 100/60s collapse into one bucket keyed on Railway's edge address. | **OPEN — S-4, HIGH** | Zero grep hits across `apps/api`. Amplified by frontend polling with no cap (composer 1.5 s, seo 3 s, billing 4 s vs a 20/min limit). `EXPLOIT: s4-trust-proxy` |
| **D** | 30 MB base64 uploads held in memory | **OPEN, MEDIUM** | `main.ts:59`; `uploadMediaSchema.dataBase64` has no `.max()` (`schemas.ts:174`), despite `main.ts:56-58` claiming a 25 MB cap is "enforced in the upload schema". The cap exists only in the engine (`api.py:376`), after the API has already parsed and forwarded the payload. |
| **E** | **VIEWER can write.** Five controllers omit `RolesGuard`, so the read-only role can delete connections, spend AI budget, wipe the catalogue, and overwrite the business profile. | **OPEN — S-1, HIGH** | `connections.controller.ts:31`, `media.controller.ts:36`, `seo.module.ts:409`, `products.module.ts:197`, `business-profile.module.ts:64`. Adding `@MinRole` to any of them today is a silent no-op. `EXPLOIT: s1-roles-guard-missing` |
| **E** | A demoted or removed member keeps their powers for up to 15 minutes | **OPEN — S-10** | `roles.guard.ts:45` trusts the token's role; no `sessionVersion` anywhere; `members.service.ts:146,176` never revoke refresh tokens. `EXPLOIT: s10-role-revocation` |

## Trust boundary 2 — API → engine

NestJS to FastAPI over `X-Internal-Secret`. Deployed on `*.railway.internal`, so today
the boundary is enforced by network placement more than by the header.

| STRIDE | Threat | Status | Evidence / control |
|---|---|---|---|
| **S** | Anyone reaching the engine impersonates the API using a published secret | **OPEN — S-5, HIGH** | Both sides default to `"dev-engine-secret"` (`env.ts:96`, `config.py:32`). No startup assertion. Grants `/tasks/*` for any `orgId`, `/storage/*`, and direct SSRF. `EXPLOIT: s5-s6-s9-config` |
| **S** | Timing oracle on the shared secret | **OPEN, LOW** | `api.py:18` uses `!=`, not `hmac.compare_digest`. |
| **T** | Task arguments forged for another tenant | **OPEN** | Follows from S-5: `orgId` is a plain field on every enqueue, trusted once the header passes. |
| **R** | — | n/a | Internal calls are not separately attributed; the API's audit row is the record. |
| **I** | Unauthenticated engine `/health` echoes raw DB/Redis exception strings | **OPEN, LOW-MED** | `api.py:76-100`; `checks["database"] = f"error: {e}"` can carry DSN fragments. Mitigated only by private networking. |
| **D** | Unauthenticated `?render=1` queues a real ffmpeg encode | **OPEN, LOW-MED** | `api.py:154`, reachable through the API's own `/health` (`health.controller.ts:56`). CPU amplification against a 2-slot worker. |
| **D** | **A hung engine holds API request slots for up to 5 minutes.** No outbound call carries a deadline. | **OPEN — B-4, MED-HIGH** | 11 `fetch()` sites, 0 `AbortSignal`. Worst case `engine.service.ts:182`, through which every enqueue *and* `/health` passes. `EXPLOIT: b4-fetch-timeouts` |
| **E** | — | n/a | The engine holds no user identity to escalate into. |

## Trust boundary 3 — engine → worker

FastAPI enqueues onto Redis (Upstash); Celery workers consume. Anything that can write
to the broker can run a task.

| STRIDE | Threat | Status | Evidence / control |
|---|---|---|---|
| **S** | Broker write access = arbitrary task execution for any `orgId` | **OPEN (by design), depends on Redis auth** | Not verified in this pass; Upstash credentials are out of repo. `task_serializer="json"` (`celery_app.py:31`) rules out pickle RCE, which is the main saving grace. |
| **T** | Consent bypass on product import | **MITIGATED** | Re-checked in the worker, not trusted from the caller (`tasks/products.py:73-84`). Correct, and the pattern other tasks should copy. |
| **T** | Paywall bypass on publishing | **MITIGATED** | Enforced independently in the worker via `locked_org_ids` (`db.py:447`), so it holds even if the API is down. Good design. |
| **R** | Which build published a post | **MITIGATED** | `build_info` control command + `worker_builds()` (`celery_app.py:98-160`). Unusually thorough. |
| **I** | Task results retain content and tracebacks in Redis | **PARTIAL** | Default `result_expires` (1 day). `dump.rdb` in the repo shows 1541 results incl. failure tracebacks — scanned, no credentials. |
| **D** | **Throughput ceiling.** Beat claims ≤20 posts/30 s; worker runs `--concurrency=2`; publish soft limit 8 min. | **OPEN, structural** | `scheduler.py:107`, `railway.worker.json`. Real ceiling is ~15–25 posts/hour and there is no per-tenant fairness — one customer scheduling 100 posts starves every other tenant. |
| **D** | A wedged task occupying a slot | **MITIGATED** | `task_soft_time_limit=20m` / `task_time_limit=25m`, per-task tighter (`celery_app.py:48-49`); `reap_stuck_posts` every 2 min. |
| **E** | — | n/a | |

Unauthenticated inbound from Paystack and Meta. Anyone on the internet can POST here.

## Trust boundary 6 — tenant → tenant

The one that decides whether this is a SaaS or an incident. Every table is `orgId`-scoped;
isolation is enforced in application code only — **there is no RLS**.

| STRIDE | Threat | Status | Evidence / control |
|---|---|---|---|
| **S** | Acting as another workspace | **PARTIAL** | `switchOrg` correctly checks membership (`auth.service.ts:398`). But C-1 lets a leaked state token reach `switch-org` in the first place. |
| **T** | Writing into another tenant's rows | **PARTIAL** | Services consistently filter `{ id, orgId }` on read-before-write — the pattern is applied uniformly and looks right. **Not proven:** no test asserts it, and a single missed `orgId` in a future query is invisible until exploited. RLS would make it structural rather than habitual. |
| **T** | Claiming another workspace's payment | **MITIGATED** | `verifyPayment` compares `metadata.orgId` to the caller's org and refuses (`billing.module.ts:456-464`), with a test. Good. |
| **R** | Cross-tenant action attribution | **MITIGATED** | `AuditLog.orgId` on every entry. |
| **I** | Cross-tenant read via IDOR | **PARTIAL** | Same as above: uniform `{ id, orgId }` filtering, zero tests. This is the single highest-value gap in the test plan. |
| **I** | **Cross-tenant read via SSRF.** A tenant makes the worker fetch an internal service and reads the reply through its own audit record. | **OPEN — S-2/S-3** | The SSRF findings are also tenant-isolation findings, which is why they rank above their CVSS. |
| **D** | One tenant starving the publish queue | **OPEN, structural** | No per-tenant fairness in `dispatch_due_posts` (`scheduler.py:107`) — `LIMIT 20` ordered by time. |
| **D** | One tenant exhausting the shared rate limit | **OPEN — S-4** | Direct consequence of the global bucket. |
| **E** | Escalation inside an org | **MITIGATED** | `assertGrantable` / `assertOutranks` (`members.service.ts:214-224`) prevent granting at or above your own rank; OWNER is never assignable. Sound, and tested. |
| **E** | Escalation across orgs | **OPEN — S-1** | A VIEWER in any org can perform owner-grade destructive actions in that org. |

## What this model assumes, and does not verify

Stated so the gaps are not mistaken for clean bills of health:

1. **Redis (Upstash) and Postgres (Supabase) network exposure and credential strength.**
   Out of repo; not inspected. If the broker is reachable with weak auth, boundary 3
   collapses and nothing in the code stops it.
2. **Supabase RLS.** Assumed off — the app connects with a privileged role and enforces
   isolation in code. Not confirmed against the live project.
3. **Railway private networking.** Boundary 2's real control today. Assumed correct
   because `.env.production.local` points `ENGINE_URL` at `*.railway.internal`. If the
   engine is publicly routable, S-5 becomes critical rather than high.
4. **Cloudflare Worker → API.** The frontend is a client-rendered SPA, so it holds no
   server-side secrets. `NEXT_PUBLIC_API_URL` is the only injected value. Low risk,
   not separately modelled.
5. **Backups and restore.** Supabase-managed; no restore has been tested and none is
   documented. Not modelled because there is nothing in repo to model.

## Ranked by expected loss, not by CVSS

1. **C-1** — leaked state ⇒ persistent account takeover ⇒ asset #1 and #4.
2. **S-1** — the read-only role is not read-only, in every workspace, right now.
3. **S-2 / S-3 / S-20** — SSRF is the cross-tenant and infrastructure read path.
4. **B-7** — not an attack, but it silently breaks the product for every TikTok
   customer within 24 hours. Highest churn cost in the list.
5. **S-4** — turns any traffic spike, or three stuck browser tabs, into an outage.
6. **S-5 / S-6** — no exploit today if configuration is correct; total compromise the
   first time it is not, with no signal that anything is wrong.
7. **S-8 / D-1** — gives revenue away rather than losing data.
8. **S-7, S-9, S-10, S-11, B-4** — real, bounded, individually cheap to fix.
